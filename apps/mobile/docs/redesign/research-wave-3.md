# Research — Wave 3 (Goals: OKR health, progress, next action)

## Scope
Goals redesign: filter Active / Archived / All via SegmentedControl, GoalCard must surface title, project, status + health as two distinct Chips, real progress (progressPercent) with ProgressBar + task-count fraction (no triple bar+percent+fraction), and next-step affordance (“+ Add next step” button when missing). Virtualized FlatList retained, placeholderData keep-previous, single FAB New Goal. Mutations (status/health/next-step/archive) + ActionSheet + modal editing preserved. References evaluated as patterns only; no code copied.

### Mobbin — Goals / OKR Lists (Asana Goals, Lattice OKRs, Todoist Filters + Notion Goals DB)

| PATTERN | Goal row is a Card (white surface, border, radius 20, shadow card) with: title 16/700 two-line clamp + project uppercase 11/600 0.6 muted; two Chips side-by-side — left status (draft/active/done/paused/archived via statusTone, blue for active) + right health (on_track green / at_risk amber / off_track red, slate when null) each dot+label; progress affordance is single ProgressBar (6h, backgroundDeep #e9edf3, fill accent/health tone) flex1 + trailing fraction “2 / 6 tasks” 12 muted semibold, never bar+fraction+percent triple; next-step row is arrow-forward-circle-outline 14 + 13/18 muted text 2-line, or when empty a secondary/ghost Button “+ Add next step” 44h (icon add 16) that opens a bottom sheet; overflow ellipsis IconButton ghost 44 absolute top-right; filter is SegmentedControl pill Active/Archived/All 44h track backgroundDeep; FAB single bottom-right “New Goal” pill. |
| WHY IT HELPS | Two-chip pattern keeps status (lifecycle) vs health (confidence) orthogonal — user scans lifecycle in blue/green/amber and risk in green/amber/red without conflating; many apps incorrectly merge them into one pill. Single bar+fraction communicates both size (total tasks) and completion without repeating percent (percent is derivable); triple encoding wastes height and narrows next-step line on 375w. Explicit “+ Add next step” button converts absent next step from passive missing-data into primary CTA — Lattice and Asana both use + CTA to drive OKR hygiene; text-only “No next step” is dead end. SegmentedControl over filter dropdown matches one-tap model Active is default 80% case, Archived rare, All diagnostic; preserved view queryKey lists(view) must refetch not client-filter for archiving correctness. |
| WHAT WE ADOPT | Cards use `Card` + `Chip kind=status value=status` + `Chip kind=health value=health muted when null` (label “No health” via Chip label, dot slate). Progress row `ProgressBar value=progressPercent flex1` + `Text completed/total tasks` where completed = linkedTasks.filter(status===done).length — honest math no fake min, clamped 0–100. Next-step row: when string → `View icon arrow-forward-circle 14 accent + Text numberOfLines2 muted 13`; when null → `Button variant=secondary size=sm leftIconName=add title="+ Add next step"` (44h min, opens editor). Overflow `IconButton ghost 44` top-right. Filter `SegmentedControl value=view options Active/Archived/All` drives `useGoalListQuery(view)` with `placeholderData:(prev)=>prev` (keeps stale rows while view switches, shows subtle “Refreshing…” 11 muted). FlatList `keyExtractor=item.id initialNumToRender 10 windowSize 5 maxToRenderPerBatch 10 removeClippedSubviews false contentContainerStyle paddingBottom floatingTabClearance 160 paddingHorizontal lg 20 paddingTop sm 8`. |
| WHAT WE REJECT | Merging status+health into single Chip or color-only dot (breaks orthogonality, a11y); circular ring per goal (overkill vs Today Momentum ring, competes hierarchy); keeping bar+“50% · 2 tasks” duplicate percent+bar (extra line, not fraction workload); text-only “No next step set” without button (no affordance); glass-blurred goal cards (perf, Android noBlur rule); `ScrollView+map` even though goals typically <50 (breaks virtualization parity); inventing `goal.progress` field — use `goal.progressPercent` exactly; `GlassSegmentedControl` legacy — use new `SegmentedControl`. |

## Cross-reference Decisions (Wave 3)

- **Query ownership & placeholders:** `useGoalListQuery(view)` gains `placeholderData:(prev)=>prev` to keep stale goals during view toggles/refetch — same pattern as `useTodayWorkspaceQuery`, `useTaskListQuery`, `useProjectListQuery`. Tab does not remount on segment change, so placeholder prevents flashing empty while new view loads. Initial pending skeleton 3× SkeletonCard; subsequent refetch uses `RefreshControl refreshing={isRefetching && !!data}` + “Refreshing…” 11 text, not spinner overlay.
- **Counters & progress:** Card shows honest `progressPercent` clamped 0–100 for bar width (never fake min). Text shows client-derived `completed / total tasks` where `completed = linkedTasks.filter(t=>t.status==='done').length` — matches server’s `progressPercent = round(completed/total*100)` from `getGoalsReadModel`, so bar and fraction stay consistent. `healthTone` not used to color bar generically (accent blue) — health remains Chip-only, avoiding overloaded color signal.
- **Status vs health orthogonality:** Two distinct Chips `kind=status` and `kind=health` both via central `chipTone`/`healthTone`/`statusTone` — no per-component `goalHealthTone` duplicate. When health null, Chip label “No health” muted opacity 0.55 via `muted` prop and dot slate #94a3b8.
- **Virtualization & clearance:** FlatList `keyExtractor=item.id initialNumToRender 10 windowSize 5 maxToRenderPerBatch 10 removeClippedSubviews false contentContainerStyle paddingBottom floatingTabClearance 160 paddingHorizontal lg 20 paddingTop sm 8` + showsVerticalScrollIndicator false — parity with Work hub. No ScrollView+map. FlatList lives inside GoalsListView, not screen ScrollView.
- **FAB & navigation:** Single `FloatingActionButton` in `goals.tsx` outside GoalsListView, `label New Goal` → `router.push("/(app)/goals/create")` typed route, `testID goals-fab`, bottom 20 right 18 inside AppScreen. Preserves deep link for create modal; no duplicate inside FlatList.
- **Next-step editing:** Preserves `useUpdateGoalNextStepMutation` + `invalidateGoalLists` (lists/detail/projects/detail). Sheet only mutates when trimmed value differs from `goal.nextStep`; empty trimmed → null. Sheet draft reset on open from source goal, isolated per goal id, not shared global draft bleed.
- **Validation:** `git diff --name-only dca2dce…HEAD` + `ls-files --others` both `apps/mobile/**` only via `awk '!/^apps\/mobile\//'` empty, `npx tsc --noEmit` exit 0, `npm test` suites pass, `git diff --check` clean. Mobile-only diff verified per wave.
