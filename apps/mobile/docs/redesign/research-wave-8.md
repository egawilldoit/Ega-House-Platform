# Research — Wave 8 (Performance + Accessibility Hardening)

## Scope
Wave 8 audits the entire `ui/mobile-redesign` branch (`dca2dceaa3baa72352ef9a6db8c80d29029fc82a` → `6702654` + Wave 8 working tree) against the spec's 14 audit areas without major redesign or dependency changes: `render frequency, FlatList/SectionList usage, timer rerenders, memoization, callback churn, large sync calculations, BlurView, shadows, keyboard behavior, safe area, query transitions, loading states, mutation loading, double submission, animations, Dynamic Type, screen-reader labels, contrast, tap targets, reduced motion`. Fix only clear issues with measurable benefit; do not cargo-cult memoize, do not upgrade deps, do not enable experimental RN/Reanimated flags, do not introduce FlashList. All edits stay inside `apps/mobile/**`.

Constraints verified before audit: lockfile scope unchanged, `glassConfig.useRealBlurOnAndroid = false` preserved, no `.github`/root package changes, no FlashList import.

## Cross-reference Decisions (Wave 8)

- **RenderItem identity authority:** `FlatList renderItem` is single stable `useCallback` per list; card components (`TaskCard`, `ProjectCard`, `GoalCard`, `TodayTaskCard`) remain un-memoized leaves — memoizing them would not help when `data` array identity changes every query refetch (even with `placeholderData`, new filtered array). Only `renderItem` reference stability matters for `VirtualizedList` diff.
