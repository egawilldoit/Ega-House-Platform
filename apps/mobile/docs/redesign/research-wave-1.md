# Research — Wave 1 (Today)

## Scope
Today workspace redesign: Daily Momentum header (tracked time ring + progress bar), 4 status sections (Planned / In Progress / Blocked / Completed), compact zero states, TodayTaskCard decomposition, Suggestions list, virtualized SectionList with Skeleton/RefreshControl. References evaluated as patterns only; no code copied. Stitch visual hierarchy is spec; data never invented.

---

### Mobbin — Daily Planner / Today View

| Field | Detail |
|---|---|
| SOURCE | Mobbin — iOS & Android production apps (Todoist Today, Things Today, Structured Day Planner, Sorted³, Sunsama daily view) — filtered for "today", "daily planner", "task list grouped" |
| PATTERN | Single-day scope header: eyebrow = localized weekday (11px uppercase, accent, tracking 1.2), title "Today" 28/900, description line `{trackedTodayLabel} tracked · {selectedCount} selected` (muted 14/20). Below header, one hero card ("Daily momentum") with date (toDateString), three stat blocks (In progress / Completed / Overdue) in horizontal row, linear progress bar whose fill width is `rounded(completedCount / total * 100)` where `total = sum(planned+inProgress+blocked+completed)`. Last content row padded `floatingTabClearance 160` above floating pill tab. Pull-to-refresh via native RefreshControl, not custom spinner overlay. Task list is SectionList with `keyExtractor=item.id`; sections never rendered via ScrollView+map. |
| WHY IT HELPS | Single-day mental model reduces decision load; eyebrow+title establish temporal context without competing with tab pill. Hero stats give at-a-glance momentum without requiring user to count rows. Mathematically honest progress (no fake 5% minimum) preserves trust — at 0/8 the bar is 0 width, not 5%. Virtualization via SectionList keeps 60fps when suggestions + 4 sections approach ~60 rows (even though typical Today is ~12–20). RefreshControl is platform-legible and avoids double-spinner (keep previous data visible during refetch). |
| WHAT WE ADOPT | Eyebrow = `new Date(date+"T00:00:00").toLocaleDateString(weekday long)`; title Today; description `{trackedTodayLabel} tracked · {selectedCount} selected` via `ScreenHeader rightSlot={<HeaderActions/>}`. Keep header already using `HeaderActions` (search+avatar) — no change. `DailyMomentum` card under header uses `Card` primitive, `ProgressBar` with `value=completedCount, max=total` (clamped 0–1, no fake min), stats row 3× flex blocks, date via `toDateString`. SectionList `contentContainerStyle.paddingBottom = floatingTabClearance (160)` and `paddingTop sm`. Maintain `useFocusEffect refetch` but keep data visible during refetch (no spinner overlay); `RefreshControl refreshing={isRefetching && !!data}`. |
| WHAT WE REJECT | Auto-hiding header on scroll / large collapsing parallax (motion cost, a11y); custom pull-to-refresh Lottie (inconsistent with platform expectations); replacing SectionList with `ScrollView + sections.map(task=>Card)` (breaks virtualization, YAGNI for large content even though Today is typically limited); adding a second tracked-time metric inside card that duplicates header's `trackedTodayLabel` (creates redundant prose, violates "no duplicate metric"); faking ring/progress at 0% to 8% minimum fill for visual weight. |

### Page Flows — Time Tracking / Tracked Today Ring

| Field | Detail |
|---|---|
| SOURCE | Page Flows — time-tracking flows (Toggl Track daily, Clockify timesheet, Sunsama focus mode) + Mobbin timer detail patterns (Apple Fitness rings, Duolingo streak ring) |
| PATTERN | Tracked-time ring is a single SVG circle (r≈22, strokeWidth 5–6) with `strokeDasharray = 2πr`, `strokeDashoffset = circumference * (1 - progress)` where `progress = completedCount/total` or `trackedSeconds/estimate` when estimate exists. No fake minimum: at 0% the stroke is fully offset (invisible), not 5% arc. Ring sits adjacent to stats (right side of Daily Momentum header row), size 52–64, color `accent` when progress<1, `success` when 100%. Accompanied by centered percentage or count label only when non-zero; never duplicate the same numeric metric shown in header description. Motion is instant width/offset change (no spring) with optional 180ms opacity fade, gated by `prefers-reduced-motion`. |
| WHY IT HELPS | Ring gives spatial completion cue without adding a second linear bar; circular occupancy is scannable when card is above the fold. Honest math avoids teaching user a non-existent baseline (a 0/6 day must read as 0, not 8%). Keeping header's `trackedTodayLabel` as single tracked truth and letting card's ring + linear bar represent `completed/total` avoids metric confusion (header=time, card=completion). Minimal motion (opacity/scale only) prevents jank when ring mounts on fast refetch. |
| WHAT WE ADOPT | Ring inside `DailyMomentum` computed as `completedRatio = total>0 ? Math.round(completedCount/total*100) : 0` and `progress = total>0 ? completedCount/total : 0` — no `Math.max(0.05, …)` floor. SVG via `react-native-svg` (already dependency 15.12.1) with `accessible=true` + `accessibilityLabel="{completedCount} of {total} completed"`; `backgroundDeep` track, fill `accent` → `successMid` when 100%. No second trackedToday string inside card (avoids duplicating header). |
| WHAT WE REJECT | Gradient sweep or segment-ring that implies sub-task breakdown (no data to support); numeric minimum fill (`max(8, ratio)`) that inflates perceived progress; animated `width/margin` ring growth (uses `strokeDashoffset` which maps to transform/opacity-friendly path); importing a new charting lib (victory/recharts) for a single arc; duplicating `trackedTodayLabel` as large hero number inside card next to ring. |

### Refero — Status Grouping (Planned / In Progress / Blocked / Completed)

| Field | Detail |
|---|---|
| SOURCE | Refero — card/list grouping systems (Linear issue board → list sections by status, Notion database groups, Asana list "Group by Status", Things "Anytime" area grouping) |
| PATTERN | Vertical sections ordered by flow: Planned → In Progress → Blocked → Completed. Each section header is a compact row: left 3px `borderLeft accent` + Title 15/800 + count pill (`surfaceMuted` or `Chip`). Section body is flat list of cards (gap `sm 8`). Zero-state is compact, not full-screen: a `Card` wrapping `EmptyState` with `icon="list-outline"` size 20–24, vertical padding `lg` not `xl*2`, title "No tasks" and description `section.emptyText` ("No planned tasks in Today." etc). Cards use left 3px accent matching status tone, status conveyed by `Chip kind="status" value={status}` (via central `chipTone`) plus text label and dot — never color alone. Priority shown by second `Chip kind="priority"` with dot. When count=0, muted styling (60% or slate) can differentiate but non-zero remains full tone per `chipTone` mapping (`in_progress→amber #fef3c7/#b45309`, `blocked→danger red #fee2e2/#dc2626`, `done→green`). |
| WHY IT HELPS | Flow order mirrors execution pipeline and keeps blocked work visually quarantined (red accent + danger Chip) so user can triage. Compact zero states avoid pushing Suggestions off-screen and preserve scroll position; full-page empty only when entire Today is 0 tasks. Single `Chip` authority (`chipTone`) prevents per-section color drift and keeps a11y non-color cues consistent. Left accent + chip dot pairs color with shape/text. |
| WHAT WE ADOPT | `TodaySection` component for header: `MobileSectionHeader`-style but via new `Card`/`Chip` primitives — title, `count={section.data.length}` via subtle pill, status-mapped `Chip` dot optional. SectionList `renderSectionHeader` → `TodaySection` title+count, `renderSectionFooter` → compact `Card`+`EmptyState` when `section.data.length===0` with `description={section.emptyText}`. Keep 4 sections (include Completed when data supports; server already returns completed array). Card left accent color from `statusTone(status).color` (muted uses `neutralMid` when done). Use `Chip kind="status"` and `Chip kind="priority"` inside `TodayTaskCard`. |
| WHAT WE REJECT | Drag-to-reorder or swipe-to-move between sections (new interaction not in code truth); separate tab per status (fragments momentum); full-screen illustration for each empty section (wastes space, pushes footer); duplicating `InfoBadge`/`GlassPill` helpers — migrate to single `Chip` primitive; collapsing sections with accordion (adds state, breaks `SectionList` virtualization simplicity); color-only encoding (no dot/text). |

### Screenlane — Compact Empty States

| Field | Detail |
|---|---|
| SOURCE | Screenlane — empty-state inventories (Linear "No issues" zero, Slack channel empty, Notion empty database view) + Refero empty cards |
| PATTERN | Compact empty: inside the same `Card` list container, icon wrap 44–64 (muted `surfaceMuted`, `radius xl`), title 17/800, description 13/600 muted centered, optional CTA `Button variant="secondary"`. Padding `xl 28` vertically, not double. For section-level empties, single compact card per section (e.g., "No tasks" + "No planned tasks in Today.") with no extra illustration. For global empties (all sections zero + no suggestions), hero card shows `emptyText="Nothing in Today yet. Add tasks from suggestions below."` as muted caption and Suggestions card header remains. Actions always full-width touch targets ≥44h. |
| WHY IT HELPS | Today often has 1–2 empty sections (especially Blocked/Completed) — compact keeps page length manageable and prevents empty sections from dominating viewport above useful Suggestions. Consistent `EmptyState` primitive means one a11y shape (icon+title+description) rather than ad-hoc Texts. Reusing `Card` wrapper preserves elevation/shadow parity. |
| WHAT WE ADOPT | `EmptyState` primitive from `components/mobile/ui/EmptyState.tsx` — `icon="list-outline"` (sections) or `"calendar-outline"` (global), `iconSize 20–24` for compact sections, `title="No tasks"`, `description={section.emptyText}`. Wrapper `Card` with `padded=false` or default padding, gap `sm` between section cards. Global zero (`todayCount===0`) caption inside `DailyMomentum` stays as muted text "Nothing in Today yet…" plus Suggestions remains visible. Suggestions empty also compact: `Text sectionEmpty "No suggestions right now."` inside Suggestions `Card`. |
| WHAT WE REJECT | Large header illustration per empty section (banner art); treating empty section as absence (no footer, so user wonders if loading); scrollview-height placeholder that forces extra whitespace; custom `EmptyState` per section style (inconsistent radii/padding); auto-hiding suggestions when all sections empty. |

## Cross-reference Decisions (Wave 1)

- **Ring math:** single source `completedRatio = total>0 ? Math.round(completedCount/total*100) : 0` shared by linear `ProgressBar (value=completedCount, max=total)` and SVG ring `progress=total>0?completedCount/total:0` → no fake floor, duplicate metric avoided (header owns `trackedTodayLabel`, card owns completion). Tested via `getTodayTaskCount` + summary counts; ring verifies via `git diff` showing no `Math.max(5` guard.
- **Section order & parity:** keep server order Planned/InProgress/Blocked/Completed as returned in `MobileTodayResponse.sections`; include Completed only when array exists (server always returns, so show even when 0 with compact empty). Empty text preserved verbatim from base ("No planned tasks in Today." etc).
- **Card authority:** one tone resolver `chipTone(kind,value)` in `theme.ts`; legacy `statusTone/priorityTone` remain aliases but `TodayTaskCard` consumes `chipTone` exclusively. Legacy `TodayTaskCard.tsx` kept as alias to avoid breaking future Work reuse; feature component is canonical.
- **Query ownership:** `useTodayWorkspaceQuery` stays in `features/today/query.ts` (no deletion). Screen keeps `useFocusEffect refetch().catch(()=>{})`, `onRefresh={()=>refetch()}`, `isRefetching && !!today` for RefreshControl. Add `placeholderData: (prev)=>prev` / `keepPreviousData` when safe to keep stale content during refetch, without masking `isPending && !data` skeleton.
- **Virtualization & clearance:** `SectionList` retained with `keyExtractor=item.id`; `contentContainerStyle.paddingBottom = mobileTheme.layout.floatingTabClearance (160)` + `paddingTop sm` maintains pill clearance. No `ScrollView+map` for sections or suggestions.
- **Design tokens:** all spacing/radii/shadow from `mobileTheme` (card 20, pill 999, shadow.card, gap sm 8, pagePadding via `AppScreen` horizontal `lg 20`). Motion tokens: press 100–140ms via `Button`/`IconButton` pressed opacity+scale 0.98; selection not animated across list; reduced motion respected via `useReducedMotion` where SVG ring animation kept minimal.
- **Validation:** mobile-only diff enforced via `git diff --name-only dca2dce…HEAD | awk '!/^apps\/mobile\//'` empty; `mobile:typecheck` (`tsc --noEmit` in apps/mobile), `mobile:test` (jest 166 suites), `git diff --check` clean.
