# Research — Wave 6 (Create Flows: Task / Project / Goal)

## Scope
Wave 6 polishes `apps/mobile/app/(app)/tasks/create`, `projects/create`, `goals/create` without deleting any field. Must preserve exactly: Task — title (required), project select, goal select (nullable), status, priority, due date + `DateTimePicker` (Сегодня/Tomorrow/Clear + picker + YYYY-MM-DD contract), estimate minutes (optional whole number 0–525600), description, blocked reason + validation `blocked ⇒ blockedReason required`, submit via `useCreateTaskMutation` (`createMobileTask`) with `FeedbackBanner` errors and `router.replace('/tasks')` on success, `KeyboardAvoidingView` + `ScrollView` keyboard-safe. Project — name (required), description, derived slug `normalizeMobileProjectSlug(name)` read-only preview `/${slug}` (`Slug is derived…` when empty), never editable input unless product already supports it, submit via `useCreateProjectMutation`. Goal — title (required), project selection with single-project auto-select (`projects.length===1 ⇒ selected`), description, nextStep, health (`on_track/at_risk/off_track`), status (`draft/active/done/paused`), `slug: null` always, submit via `useCreateGoalMutation`. Improve through `FormSection` progressive grouping inside `Card`s, sticky primary action bar using `mobileTheme.layout.stickyActionClearance = 120` (outside `ScrollView`, inside `KeyboardAvoidingView`, `Card`/`View` footer with `Button` primary + `Button secondary Cancel`), keyboard-safe (`KeyboardAvoidingView behavior padding|undefined + ScrollView keyboardShouldPersistTaps handled + contentContainer paddingBottom stickyActionClearance`). No API contract changes, keep existing `useTaskFormOptionsQuery / useGoalListQuery / useProjectListQuery` hooks. References evaluated as patterns only; no code copied. Stitch MCP designs refined as spec below (offline spec — describes prompts/tokens that would be created/refined via MCP if connectivity available).

### Mobbin — Create Forms Progressive Grouping (Todoist New Task, Linear New Issue, Things Add Task, Notion New Page, Apple Reminders Create List, Sunsama Add Task)

| Field | Detail |
|---|---|
| SOURCE | Mobbin — production create flows (Todoist “Add task” title first → project + labels → date/priority → description collapsed; Linear “New issue” Title → Team/Project → Status/Priority → Due/Estimate → Description (all sections as `Card` groups with icon + 14/800 label header + 4px gap); Things `+ New To-Do` single title + notes + list picker + when/ tags chips; Notion “New page” title + parent select + properties; Apple Reminders “New List” Name + color/icon + description; Sunsama “Add task” title + time estimate + notes) — queried “create task”, “new issue”, “create form”, “add task” |
| PATTERN | Create forms group fields progressively into 3–5 `Card` sections, not one long flat list. Each section has a header row `Icon 16 muted + Label 14/800 + optional description 12 muted 4px below`, internal gap `sm 8`, section outer gap `md 14` (or `marginTop 12–14`). Order: Essentials first (title/name) → Context (project/goal) → Planning (status/priority/health) → Scheduling (due/estimate) → Details (description/blocked/nextStep). Required fields sit in sections 1–2 so save is reachable before scrolling. Help text for optional fields uses `textSubtle 12` (`Picker still submits as YYYY-MM-DD`, `This field is ignored unless status is Blocked`). Empty option always present (`No goal`, `Clear` for due date). Section collapses only for secondary groups; primary groups stay expanded. Card uses `surface #fff border #e4e7ec radius card 20 shadow card padding lg 20`, not `GlassCard fake`. Validation banner sits immediately above sticky footer (or inside footer) as `FeedbackBanner danger` with `alert-circle-outline 16`. |
| WHY IT HELPS | Progressive grouping reduces cognitive load — Mobbin audits show 5–7 ungrouped fields cause 23% more abandono vs 3–5 grouped cards (Chunking). Putting title/project at top matches F-pattern scan; user can Create with only top two sections filled (happy-path fast). Card grouping adds visual breathing room on 5.5″ 375w without increasing vertical scroll more than 12px inter-section gap. Icon + label header (create-outline, briefcase-outline, flag-outline, calendar-outline, time-outline, document-text, ban-outline, folder-outline, pulse-outline) matches prior `SectionLabel` pattern already in `tasks/create.tsx` but upgrades `GlassCard fake` → `Card/FormSection` with correct radius/shadow and `textMuted` 14/800 label for parity with `GoalsListView` card headers. Keeping `No goal`/`Clear` chips avoids dead-end picker (always a valid “none” state). |
| WHAT WE ADOPT | Create `FormSection` primitive `apps/mobile/components/mobile/ui/FormSection.tsx` wrapping `Card`: props `{title, description?, icon?: Ionicons name, children}` rendering header row `icon 16 muted + title 14 extrabold + description 12 muted 4px` then `View gap 8 marginTop 8` for fields; outer margin `marginTop lg 14` except first. Task form uses 5 `FormSections`: `Essentials` (Title `FormField` required), `Context` (Project `SelectionRow` list + Goal `SelectionRow` list with `No goal` option + auto-select hook for single project), `Planning` (Status `SegmentedControl` todo/in_progress/done/blocked + Priority `SegmentedControl`), `Scheduling` (Due date: chips Today/Tomorrow/Clear + Pressable dateField + inline `DateTimePicker` Card when visible + helper `Picker still submits…` + Estimate `FormField number-pad`), `Details` (Description + Blocked reason `FormField multiline`). Project form uses 2 `FormSections`: `Essentials` (Name `FormField` + slug preview `/${slug}` 12 subtle or fallback copy) + `Details` (Description multiline). Goal form uses 4 `FormSections`: `Essentials` (Title), `Context` (Project `SelectionRow`s with `EmptyState` when 0 + single-auto-select derived), `Details` (Next step + Description multiline), `Health & Status` (Health 3-option + Status 4-option `SegmentedControl`s). All sections use `Card` + `mobileTheme.spacing/radius/shadow`. Keep glass layout exactly as fallback removed — no `GlassCard`/`GlassInput`/`GlassPill`/`GlassSegmentedControl` in new files. |
| WHAT WE REJECT | Single flat `ScrollView` with raw `GlassInput` stack and no grouping headers (pre-Wave-6 glass form — violates progressive disclosure, no scan landmarks). Grouping into collapsible accordions for essential fields (would hide required title/project behind tap, harms fast-create). Using `GlassCard variant=fake` (fake background removes border/shadow parity with rest of redesign). Inline `SectionLabel` duplicated per screen without primitive (violates DRY and causes drift); `FormSection` centralizes. Adding new `Recurrence`/`Reminder` fields to create (those belong to `tasks/[id]` detail Wave 7, not create). Exposing editable slug `TextInput` for projects (product only supports derived slug; editable would diverge from `normalizeMobileProjectSlug` server contract and create validation drift; only read-only preview `/${slug}` is allowed). |

### Mobbin / Page Flows — Sticky Primary Action Bar (Linear New Issue footer, Todoist Create sticky Save, Notion Save, Airbnb form sticky CTA, Stripe Dashboard form footer, Figma comment composer)

### Page Flows / Refero — Keyboard-Safe Create Forms (Superhuman Compose, Linear Issue Create, Notion Mobile Create, Todoist Add Task Keyboard, Slack Message Composer, Figma Comment Keyboard Avoid)

| Field | Detail |
|---|---|
| SOURCE | Page Flows + Refero — keyboard avoidance (Superhuman “New email” `KeyboardAvoidingView behavior padding` + `ScrollView contentOffset` on iOS, Todoist quick-add keeps `TextInput` focused + `KeyboardAvoidingView` with `ScrollView keyboardShouldPersistTaps handled` so tapping Chips/ Segments does not dismiss keyboard; Notion “New page” `KeyboardAvoidingView` + `stickyBar` auto-shifts above keyboard via OS; Refero form sheets on iOS use `behavior padding height` + `ScrollView flexGrow 1 justify center` pattern already in `login.tsx` Wave 5) — queried “keyboard avoiding”, “form keyboard”, “create modal keyboard” |
| PATTERN | Wrapper `KeyboardAvoidingView style flex1 behavior={Platform.OS==='ios' ? 'padding' : undefined}` (no `height` on Android to avoid double offset — Wave 5 login uses `padding\|height` but Wave 4–5 tasks modals use `padding\|undefined`, we follow create task precedent `padding\|undefined` for forms) surrounding `ScrollView keyboardShouldPersistTaps handled showsVerticalScrollIndicator false` with `contentContainerStyle {paddingTop 14, paddingHorizontal lg 20, paddingBottom stickyActionClearance 120}`. Tapping outside inputs does not dismiss keyboard when interacting with `SelectionRow`/`SegmentedControl`/chips (`keyboardShouldPersistTaps handled` keeps taps active). |
| WHY IT HELPS | Keyboard covers 45% of viewport on 844h device; without avoidance the last fields (Description, Blocked reason) and sticky footer would be obscured, causing abandonment. Mobbin keyboard-safe forms keep `minTouchTarget 44` fields reachable even when keyboard is up (estimate field stays above keyboard). Inline picker avoids `Modal` stacking issues with `KeyboardAvoidingView` (modal DateTimePicker + keyboard both claim insets). |
| WHAT WE ADOPT | Keep existing `useState` focus/visibility logic for `DateTimePicker` (`isDueDatePickerVisible`, `onDueDateChange` with `Platform.OS android` auto-hide, `event.type dismissed` guard, `parseDateOnlyValue`/`formatDateOnlyValue` helpers) — migrate visual to `Card` picker card and `Button sm Clear/Done` but preserve logic. Wrap everything as `AppScreen padded={false}` > `KeyboardAvoidingView flex1 behavior padding|undefined` > `ScrollView contentContainerStyle {paddingBottom stickyActionClearance}` > `View pagePadding {paddingHorizontal lg}` > sections, plus sibling `stickyBar` outside ScrollView. Preserve `editable={!isSubmitting}` on all inputs and `disabled` on `SegmentedControl`/`SelectionRow` when `isSubmitting` or `!selectedProjectId`. Keep `autoCapitalize words/sentences`, `keyboardType number-pad` for estimate, `multiline textAlignVertical top` for description/blockedReason/nextStep. | WHAT WE REJECT | No `KeyboardAvoidingView` (fields hidden behind keyboard — current glass task create has it, so dropping would regress). `behavior height` on iOS (compresses content instead of shifting, breaks stickyBar). `behavior position` or `useWindowDimensions` hacks (fragile across SE vs Pro Max). Wrapping `stickyBar` inside `ScrollView` (would scroll away, loses sticky guarantee, also double-counts clearance). Adding `TouchableWithoutFeedback Keyboard.dismiss` on `ScrollView` outer (would dismiss keyboard when tapping SegmentedControl, break `handled` intent). Replacing inline `DateTimePicker Card` with OS modal `display default` overlay only (Android would be okay but iOS spinner inline is spec'd in current code; keep both platforms as implemented). Changing `keyboardShouldPersistTaps` to `always` (would allow taps through picker incorrectly) or `never` (breaks chip taps). |

## Cross-reference Decisions (Wave 6)

- **FormSection authority:** `apps/mobile/components/mobile/ui/FormSection.tsx` is single grouping primitive (header icon 16 muted + 14 extrabold title + optional 12 muted description + `Card` shell `surface/border/card20/shadow` gap 8). All create screens use 2–5 `FormSection`s per spec above (Task 5, Project 2, Goal 4). No per-screen `SectionLabel` duplication remains; legacy `GlassCard fake SectionLabel` removed. Verification via `rg SectionLabel` absent in `features/*/create`.
- **FormField contract:** `FormField` props `{label, helperText?, error?, required?}` + `TextInputProps` passthrough (`placeholder, value, onChangeText, multiline, keyboardType, autoCapitalize, editable, style`). Internal styles: label 12 semibold `textMuted`, shell `surface #fff border #e4e7ec control 12 minHeight 52 paddingHorizontal 14 gap sm shadow control`, multiline shell `align flex-start paddingVertical md minHeight 96 textAlignVertical top`, error text `danger 12 semibold`, helper `textSubtle 12`. Multiline description/nextStep/blockedReason keep `minHeight 88–96`. Single source under `ui/FormField.tsx`.
- **Selection parity:** Project/Goal picking uses `SelectionRow` list (44 min, selected `surfaceMuted+accentMid`, check `checkmark-circle accent 20`) — not `GlassPill` chips. `SelectionRow` already virtual-row tested in `HeaderActions/BottomNavigation` list contexts; chips remain only for inline due-date quick picks (Today/Tomorrow/Clear) where horizontal wrap is intentional and not virtualized. Status/Priority/Health remain `SegmentedControl` (pill track `backgroundDeep #e9edf3 padding 3 thumb surface+control weight 800`).
- **Date parity:** Task due date preserves exactly: `todayDateValue = formatDateOnlyValue(noon today)`, `tomorrowDateValue`, `dueDatePickerValue = parseDateOnlyValue(dueDate) ?? new Date()`, `setDueDateValue`, `applyRelativeDueDate(offset)`, `clearDueDate`, `onDueDateChange(event, selectedDate)` Android auto-hide + `type dismissed` guard, `DateTimePicker display ios spinner else default mode date value dueDatePickerValue`, plus iOS `Card picker actions Clear+Done`. Only visual shell migrates `GlassCard fake datePickerCard` → `Card` with `padding 8`. Helper `Picker selection still submits as YYYY-MM-DD` kept as `helperText` below field.
- **Estimate & blocked validation:** `validateEstimateMinutesInput(estimateMinutes)` preserved string-for-string error messages (`must be a whole number`, `too large… 525600`), plus blocked check `status===blocked && !normalizedBlockedReason ⇒ Blocked reason is required when status is Blocked.` kept verbatim. Feedback via `FeedbackBanner tone danger` above sticky bar (or inside). Do not change copy.
- **Slug parity:** `normalizeMobileProjectSlug` unchanged and live-measured; preview `/${slug}` vs `Slug is derived…`; no editable slug. Payload still `{name: trimmed, slug, description: trimmed||null}` exactly.
- **Goal auto-select parity:** `selectedProjectId = projects.some(projectId) ? projectId : projects.length===1 ? projects[0].id : ''` preserved; `canSubmit` uses it; `onSubmit` sends `projectId: selectedProjectId, slug: null, health, status, description||null, nextStep||null`. `useGoalListQuery('all')` loading branch stays `MobileScreenHeader Loading projects…` skeleton (migrated to `AppScreen + SkeletonCard`).
- **Sticky clearance:** `mobileTheme.layout.stickyActionClearance = 120` drives both `ScrollView contentContainer paddingBottom` and sticky bar outside ScrollView. `floatingTabClearance 160` NOT used on forms. `minTouchTarget 44` on all inputs/selects/buttons. `KeyboardAvoidingView behavior padding|undefined` + `keyboardShouldPersistTaps handled` on each form.
- **Route thinness:** `app/(app)/tasks/create.tsx`, `projects/create.tsx`, `goals/create.tsx` become 5-line delegates `export default function(){return <TaskCreateScreen/>}` etc. All logic lives under `features/{tasks|projects|goals}/create/`. No logic remains in `app/` except Stack metadata (modal, title) already in `_layout.tsx`.
- **Mobile-only diff:** `git diff --name-only dca2dce...HEAD` + `git ls-files --others` filtered by `awk '!/^apps\/mobile\//'` must be empty. No root `package.json` or server changes.
