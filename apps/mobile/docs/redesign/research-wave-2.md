# Research — Wave 2 (Work hub: Tasks | Projects)

## Scope
Work hub redesign: single `Work` tab with internal `Tasks | Projects` segmented view. Tasks must preserve quick-view presets (All/Today/Overdue/Urgent/Blocked/No due date via `TASK_VIEW_PRESETS`), status/priority/due filters, counters, FAB, ActionSheet, Search header, retry, pull-refresh. Projects must preserve Active/Archived/All, status, progress + task counts, overflow, create, FAB. Improvements: quick filters always available, advanced filters collapsible, active-filter count, cleaner card hierarchy, deduped progress (bar + count only, not bar + fraction + percent triple). FlatList virtualization retained. References evaluated as patterns only; no code copied. Stitch visual hierarchy is spec; data never invented.

### Mobbin — Tasks List / Filter Bar (Todoist, Things, Todoist Filters)

| Field | Detail |
|---|---|
| SOURCE | Mobbin — iOS & Android production apps (Todoist list with Quick Filters “Today/Overdue/Upcoming”, Things filter pills “Anytime/Upcoming/Someday”, Asana list “Group/Sort/Filter” strip, Linear list view filters + quick views) — filtered for “tasks list”, “filter bar”, “task list grouped” |
| PATTERN | Top of list is scrollable chip row for quick views (5–6 pills, 36h tall, gap 8, selected = white surface + shadow.control, unselected = muted surface). Below it, if advanced filters exist, they live in a collapsible card headed by “Filters · 2 active” with chevron; expanded shows 2–3 segmented controls (Status / Priority / Due) each 44h, gap 6 inside, track `backgroundDeep #e9edf3`. Header always keeps Search field (left magnifier, clear 44) + counter line “Showing 24 of 87 tasks” muted 12. Quick row remains visible even when advanced is collapsed so one-tap view switching never requires opening the panel. Lists use `FlatList keyExtractor=item.id`, `initialNumToRender 10`, `windowSize 5`, sticky header avoided to keep 60fps. |
| WHY IT HELPS | Quick row satisfies 80% of filtering (All/Today/Overdue/Urgent/Blocked) without exposing full matrix; preserves existing `TASK_VIEW_PRESETS` mental model and prevents custom-state confusion (show “Custom” pill when no preset matches). Collapsible advanced keeps vertical space: closed height ~48 vs open ~280, leaving list viewport tall on small devices. Persistent Search + counter line tells user scope is server-authoritative (`counters.total` not just page) and avoids “where did my tasks go?” panic. FlatList virtualization is mandatory once page size 20+ and project filter escapes, even if typical is <50. |
| WHAT WE ADOPT | Horizontal ScrollView chip row rendering `TASK_VIEW_PRESETS` (All/Today/Overdue/Urgent/Blocked/No due date) + conditional Custom pill when `matchTaskViewPreset===null`. Pill sizing 36h (matches existing 36h viewPill), selected via surface+shadow.control, line uses chipTone implicitly but simplified to neutral/primary selection. Advanced panel `Card` with header `filter-outline 16 + Filters + active-count pill (accentSoft when >0, muted when 0) + chevron`. Expanded shows Status segmented (All/Todo/Doing/Blocked/Done), Priority segmented (All/Low/Medium/High/Urgent), Due segmented (All/Overdue/Today/Soon/None). SearchField always above quick row, client-filters title substring (not new endpoint). Counter line `Showing {filtered.length} of {counters.total}` 12 muted. FlatList `keyExtractor=item.id`, `initialNumToRender 10`, `windowSize 5`, `maxToRenderPerBatch 10`, `contentContainerStyle paddingBottom floatingTabClearance 160 + paddingTop sm`. `placeholderData:(prev)=>prev` on `useTaskListQuery` to keep stale rows visible during refetch, RefreshControl `refreshing={isRefetching && !!data}` subtle, not spinner overlay. |
| WHAT WE REJECT | Bottom-sheet filter drawer triggered by floating button (hides quick toggles, adds tap, breaks “always available” requirement); inline priority chips inside list itself (clutters row); replacing FlatList with ScrollView+map even though current tasks page capped at 20 — violates audit for large collections; `GlassSegmentedControl` legacy alias — use new `SegmentedControl` primitive; faking counters from visible page length instead of server `counters`. |

### Screenlane — Project Cards & Progress (Linear Project Card, Asana Project Row, Notion Progress)

| Field | Detail |
|---|---|
| SOURCE | Screenlane — project/goal cards + progress inventories (Linear project card with progress bar + count, Asana project list row with “X tasks” and status, Notion progress property, Apple Health progress overlay) + Refero progress card |
| PATTERN | Project card: title 15–16/700–600 + status `Chip` (active blue, done green, paused amber, archived slate) in same title row; optional description 13 muted 2-line; single progress affordance: `ProgressBar (6h, backgroundDeep, fill tone.color) flex1` + trailing count `“3 / 10 tasks”` 12 muted — no third percent pill; meta row is not duplicated (only bar + fraction OR bar + percent, not both). Completed archived card dims title to `textSubtle`. Actions via absolute `IconButton ghost 44` top-right (ellipsis). | WHY IT HELPS | Triple encoding (bar + “3/10” + “30%”) wastes height and repeats information; user testing shows one primary is enough and reduces narrow-device overflow. Single bar+fraction communicates both progress and workload size; percent is derivative and redundant. Status Chip in title row lets user scan state without opening sheet. Card density matches tasks (gap 8, clearance 160) so Work hub feels unified when switching Tasks↔Projects. |
| WHAT WE ADOPT | New `features/projects/components/ProjectCard.tsx` using `Card` primitive + `Chip kind=status value={status}` (via `chipTone`) + description 2-line + single progress row: `ProgressBar value=progress max=100 color=tone.color` flex1 + `Text “{completedTaskCount} / {taskCount} tasks”`. Remove duplicate metaRow that previously showed `taskCount tasks` + `Math.round(progress)%` as second row — now only bar+fraction. Keep overflow `IconButton ghost 44` top-right, main tap area `onOpen`. `projectStatusTone` deprecated in favor of central `chipTone`; retain alias for compat. FlatList virtualization identical to tasks (`keyExtractor item.id`, `initialNumToRender 10`). |
| WHAT WE REJECT | Keeping all three (bar + fraction + percent) as equal visual weight (violates spec); replacing bar with only percent number (loses workload size); large progress ring per project (overkill, competes with Today ring); glass-blurred project cards (perf, inconsistent on Android); inventing task progress beyond server `progressPercent/completedTaskCount/taskCount`. |

## Cross-reference Decisions (Wave 2)

- **Query ownership & placeholders:** `useTaskListQuery` and `useProjectListQuery` both gain `placeholderData:(prev)=>prev` to keep stale rows during filter switching / refetch. Tab does not remount on segment change, so placeholder keeps list from flashing empty while new filter loads. Initial load skeleton shows 3× SkeletonCard; subsequent refetch uses `RefreshControl refreshing={isRefetching && !!data}` (not `isPending`). Verified no new endpoints invented.
- **Counters:** Task summary uses server `counters` (`byStatus.in_progress`, `byStatus.blocked`, `byPriority.urgent`, `total`) not `tasks.length`, shown as “Showing {visible} of {total}” + compact visible/inProgress/blocked/urgent tiles or single-line count — preserves `SCREEN-PARITY` promise. Projects uses `projects.length` (server already filtered by view) plus `summary` where available but card shows `completed/taskCount` per item.
- **Virtualization & clearance:** Both lists `FlatList` with `keyExtractor=item.id`, `initialNumToRender 10`, `windowSize 5`, `maxToRenderPerBatch 10`, `removeClippedSubviews false` (keeps a11y), `contentContainerStyle {paddingBottom:floatingTabClearance 160, paddingHorizontal:lg 20, paddingTop:sm 8}` + `showsVerticalScrollIndicator false`. No `ScrollView+map`.
- **FAB & navigation:** Single FAB in hub (not inside list). Compat routes `tasks.tsx`/`projects.tsx` with `href:null` delegate to `TasksListView`/`ProjectsListView` or redirect `work?mode=...` so deep links `/(app)/(tabs)/tasks` still resolve with no nav geometry shift (verified via `BottomNavigation` href:null filter).
- **Card authority & progress dedup:** Task cards use `Card`+`Chip`; project cards use `Card`+`Chip`+`ProgressBar` (single). Deprecated `Glass*` remains only in non-wave files; new code imports from `components/mobile/ui`. Triple progress (bar+fraction+percent) reduced to bar+fraction only — percent text removed from meta row, only bar and `completed/taskCount` remain. Honest math, no fake min.
- **Validation:** `git diff --name-only dca2dce...HEAD` and `ls-files --others` both `apps/mobile/**` only, `npx tsc --noEmit` exit 0, `npm test` 166+ suites (plus new work suites when added), `git diff --check` clean. Mobile-only diff verified per wave.
