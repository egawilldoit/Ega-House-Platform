# Hono API Server Deployment (`@ega/server`)

Status: **VERCEL RUNTIME BUNDLE HARDENED** (2026-08-25).

The production API is deployed as a separate Vercel project with Root Directory
`apps/server` and the native Hono framework preset. Its public origin is
`https://ega-api.egawilldoit.online`.

## Decision

V1 hosting target for `apps/server`: **Vercel Functions using the native Hono
preset**, deployed independently from the Next.js web project.

The repository keeps source-first npm workspaces for local development, tests,
web, and mobile. The Vercel API deployment adds one production-only packaging
step: esbuild bundles the Hono entrypoint and all runtime `@ega/*` workspace
code into a self-contained JavaScript entrypoint before Vercel traces the
function.

| File | Runtime | Role |
| --- | --- | --- |
| `apps/server/index.ts` | Vercel build source | Canonical production source entrypoint; default-exports `createProductionApp()`. |
| `apps/server/index.js` | Vercel generated artifact | Self-contained Node 22 ESM bundle generated by `npm run build:vercel`; ignored by Git. |
| `apps/server/src/serve.ts` | Long-lived Node process | Local/dev runtime (`npm run dev --workspace @ega/server`). |

The production bundle and local server wrap the same `createProductionApp()`,
so routing, bearer authentication, `/health`, `/ready`, and JSON error shapes
remain one code path.

## Why the bundle step exists

The internal packages (`@ega/application`, `@ega/contracts`,
`@ega/data-access`, `@ega/domain`) intentionally expose TypeScript source from
their workspace package exports. That works in the repository and in the
Next.js app, which transpiles those packages, but the native Hono Vercel
function tracer did not include those workspace source files in the deployed
runtime. The observed production failure was:

```text
ERR_MODULE_NOT_FOUND: Cannot find module
/var/task/node_modules/@ega/application/src/index.ts
```

This occurred before any Supabase request. It was a deployment-artifact defect,
not a database credential defect.

`apps/server/vercel.json` now runs:

```text
npm run build:vercel
```

and `apps/server/package.json` defines the bundle as:

```text
esbuild index.ts --bundle --platform=node --format=esm --target=node22 --outfile=index.js
```

Because the generated `index.js` is a complete runtime artifact, Vercel no
longer needs `packages/*/src` to exist inside the function filesystem.

## Production packaging proof

`apps/server/test/vercel-runtime-bundle.test.ts` is the deployment regression
for this boundary. It:

1. removes any stale generated bundle;
2. runs the same `build:vercel` command Vercel runs;
3. requires `apps/server/index.js` to exist;
4. rejects retained runtime imports of internal `@ega/*` workspaces;
5. copies only the generated JavaScript file to a temporary isolated directory;
6. imports it there with no monorepo workspace source available; and
7. proves `GET /health` returns `200 {"status":"ok"}`.

This specifically guards the production failure mode that ordinary source-tree
typechecks and tests cannot detect.

## Vercel project configuration

The API Vercel project must use:

- Repository: `egawilldoit/Ega-House-Platform`
- Root Directory: `apps/server`
- Framework Preset: Hono
- Production branch: `main`
- Output Directory override: disabled / `null`
- build command: supplied by `apps/server/vercel.json`
- custom domain: `ega-api.egawilldoit.online`

The checked-in root web `vercel.json` and `apps/server/vercel.json` declare the
intended main-only Git deployment policy:

```json
{
  "*": false,
  "main": true
}
```

Wave 00 added a fail-closed Vercel Ignored Build Step for the API project root:
only `VERCEL_GIT_COMMIT_REF=main` may build; an absent or non-main ref is
skipped. The exact Wave 00 API head
`6f71ebdf6f67f8c77f371b28eefba4487a0930b8` received the observed external
status `Canceled by Ignored Build Step`, with no successful feature-branch
preview. This proves the checked-in build guard and its smoke behavior, not
the complete connected-project settings or a production deploy. A production
deployment remains external Vercel state and must be verified against its
exact Git SHA.

Do not add a catch-all rewrite to an `api/index.ts` generic function. The native
Hono preset discovers the project-root entrypoint directly; the production
build intentionally generates `index.js` next to `index.ts`.

## Environment contract

Read at runtime by `src/env.ts`; values are not baked into the bundle:

| Variable | Required | Notes |
| --- | --- | --- |
| `SUPABASE_URL` | yes (or fallback) | Valid http(s) URL of the Supabase project. |
| `SUPABASE_ANON_KEY` | yes (or fallback) | Anon/publishable key used with caller JWTs and RLS. |
| `NEXT_PUBLIC_SUPABASE_URL` | fallback | Accepted when `SUPABASE_URL` is unset. |
| `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` | fallback | Accepted when `SUPABASE_ANON_KEY` is unset. |
| `PORT` | local `serve.ts` only | 1–65535, default 3001. |

Never use the Supabase service-role/secret key for the mobile Hono API. Request
identity comes from the verified bearer token and data access remains subject
to Supabase RLS.

Missing Supabase values make the production application refuse to initialize
with an explicit configuration error. `/health` proves the function can boot;
`/ready` is the first endpoint that actually probes Supabase.

## Production verification sequence

After a production deployment of the exact `main` SHA:

1. `GET https://ega-api.egawilldoit.online/health`
   - expected: `200 {"status":"ok"}`
2. `GET https://ega-api.egawilldoit.online/ready`
   - expected: `200 {"status":"ok"}` when Supabase is reachable and configured
   - `503 {"status":"unavailable"}` means the function booted but the dependency probe failed
3. `GET https://ega-api.egawilldoit.online/api/projects` without Authorization
   - expected: canonical `401 UNAUTHENTICATED`
4. Run mobile L8 against the production origin:

```text
MOBILE_PRODUCTION_BASE_URL=https://ega-api.egawilldoit.online npm run verify:mobile -- --levels 8
```

## Mobile base URL

The committed production mobile environment points to:

```text
EXPO_PUBLIC_API_BASE_URL=https://ega-api.egawilldoit.online
```

All canonical mobile surfaces use the Hono API (`/api/auth/*`, `/api/timer/*`,
`/api/projects*`, `/api/goals*`, `/api/tasks*`, `/api/today*`). The Next.js web
origin is not the mobile API authority.
