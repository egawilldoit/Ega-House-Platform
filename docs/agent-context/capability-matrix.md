## Reading this matrix

`COMPLETE` means the named user workflow has a traced static implementation across its intended current surfaces and behavior-focused tests; it does **not** assert deployment or runtime success. `PARTIAL` means a user-facing implementation exists but one or more required trace stages or surfaces are absent. `INTERNAL_ONLY` means the code is a support capability with no standalone user surface. `MISSING` and `BROKEN` are used only for absent or contradicted stages, respectively. Every row also carries `NOT_RUNTIME_VERIFIED` unless a precise external/runtime observation is cited.

Evidence shorthand:

- `D/A` — domain/application owner; `P` — persistence adapter and root schema/migration; `H` — registered Hono route; `C` — `@ega/contracts`; `AC` — `@ega/api-client`; `W` / `M` — web / mobile exposure; `T` — behavior-focused test source.
- A path is a concrete checked-in reference at the snapshot. Tests are static evidence until their exact command, revision, and external dependencies are recorded.
- `—` means no matching implementation was found in the named layer; it is not inferred from a similarly named file.

The common authenticated Hono seam is `apps/server/src/app.ts:126-138`: bearer identity is derived in the middleware before these routes compose application and request-scoped data access. Root schema authority remains `src/db/schema.ts`; migration files below show that a table definition is versioned, not that it is applied anywhere.

## Ranked convergence opportunities (proposed Waves 02–12)

These ranks use user-loop value and semantic-risk reduction, not endpoint counts. Wave labels are proposed owners for planning; they do not authorize implementation.

1. **Wave 02 — Search canonicalization.** Put query/filter/ranking policy behind an application read model, contract, Hono route, and API client. Search currently produces different web SQL and mobile in-memory result sets, making a common workspace feel inconsistent.
2. **Wave 03 — Startup/Shutdown shared workflow decision.** Resolve whether these are durable workflow lifecycles or presentations over existing Task/Review state, then move only the approved semantics out of web-local Supabase services. This closes the daily loop on mobile without creating parallel truth.
3. **Wave 04 — Notifications completion and external proof.** Add a web notification-center projection, then execute controlled migration/provider/device/RLS verification. Reminders have immediate user value but currently have a web surface gap and no external delivery proof.
4. **Wave 05 — Project/Goal contract extraction.** Move the duplicated `@ega/api-client/src/types.ts` wire shapes into `@ega/contracts`; add contract/transport parity tests. This removes a silent drift seam from the core Project → Goal path.
5. **Wave 06 — Time Context configuration.** Add a deliberately scoped owner-facing timezone/week-boundary UX (or explicitly retain it as internal) and verify it through review, friction, and operator flows. Correct temporal context changes many user-visible calculations at once.
6. **Wave 07 — Health web exposure and Operator mobile completion.** Expose Health's existing typed Hono/client flow on a rendered web surface and Operator's on mobile, after deciding whether Health needs a named persistence/read-model owner. This leverages already-tested analysis/proposal semantics instead of reimplementing them in UI.
7. **Wave 08 — Work Analytics shared read model.** Extract only stable analytics/evidence calculations from web-local services, preserving presentation-specific chart code. It makes Reviews, Timer insights, and mobile analytics agree without forcing UI convergence.
8. **Wave 09 — Runtime verification ladder.** Record exact deployed Hono health/ready/auth/RLS checks and targeted mobile/device paths for the completed static flows. This is the highest confidence gain across all rows, but should follow the semantic convergence work above.
9. **Wave 14 candidate — documentation/governance cleanup.** Reconcile stale prose and instruction-size debt below; do not use it to claim product completion.
